# 06.1.3 - Oradores

> Sistema Inteligente de Programação de Discursos (SIPD)

**Versão:** 1.2

---

# Objetivo

Este documento especifica os Casos de Uso relacionados ao módulo de Oradores do SIPD.

O módulo é responsável pelo cadastro, consulta e manutenção dos oradores, seus temas preparados, histórico de apresentações e eventual vinculação com uma conta de usuário.

O cadastro do orador é independente da existência de uma conta de acesso.

# UC-ORA-001 — Cadastrar Orador

## Objetivo

Permitir o cadastro de um novo orador na base global do SIPD.

## Atores

- Coordenador
- Editor, conforme permissão
- Administrador Global

## Permissões

O usuário deverá possuir permissão para cadastrar oradores.

O cadastro deverá respeitar a congregação de origem do orador.

## Gatilho

O usuário seleciona a opção Cadastrar Orador.

## Pré-condições

- Usuário autenticado.
- Usuário possui permissão para cadastrar oradores.
- Congregação de origem definida.

## Fluxo Principal

1. O usuário acessa o cadastro de oradores.
2. Seleciona Novo Orador.
3. Informa os dados necessários.
4. Define a congregação de origem.
5. O sistema valida os dados.
6. O sistema verifica possíveis duplicidades.
7. O usuário confirma o cadastro.
8. O sistema registra o orador.
9. O sistema registra o evento no histórico.

## Fluxos Alternativos

### FA-01 — Orador já cadastrado

O sistema identifica um possível cadastro existente e apresenta os dados para que o usuário possa verificar se trata-se do mesmo orador.

### FA-02 — Orador possui conta

Caso o orador já possua uma conta no sistema, o cadastro poderá ser vinculado à conta existente conforme as regras de vinculação.

### FA-03 — Orador sem conta

O cadastro é criado normalmente sem uma conta de acesso vinculada.

## Fluxos de Exceção

### FE-01 — Dados obrigatórios ausentes

O sistema informa os campos que precisam ser preenchidos.

### FE-02 — Falha ao salvar

O sistema informa que não foi possível concluir o cadastro.

## Pós-condições

O orador passa a existir na base de oradores e fica vinculado à sua congregação de origem.

## Regras de Negócio Relacionadas

- RN-020
- RN-024
- RN-102

## Entidades Envolvidas

- Orador
- Congregação
- Usuário
- Histórico

## Casos de Uso Relacionados

- UC-ORA-007 — Vincular Conta ao Orador

## APIs Relacionadas

- POST /oradores

## Telas Relacionadas

- Oradores
- Novo Orador

## Observações

O cadastro do orador não exige que exista uma conta de usuário.

A existência de uma conta será representada pelo vínculo entre o cadastro do orador e o usuário correspondente.

# UC-ORA-002 — Editar Orador

## Objetivo

Permitir que usuários autorizados atualizem os dados permitidos de um orador.

## Atores

- Coordenador
- Editor, conforme permissão
- Administrador Global

## Permissões

O usuário deverá possuir permissão de edição de oradores.

## Gatilho

O usuário seleciona um orador e solicita a edição.

## Pré-condições

- Usuário autenticado.
- Orador existente.
- Usuário possui permissão de edição.

## Fluxo Principal

1. O usuário consulta o orador.
2. Seleciona Editar.
3. O sistema verifica as permissões.
4. O sistema apresenta os dados editáveis.
5. O usuário realiza as alterações.
6. O sistema valida os dados.
7. O usuário confirma.
8. O sistema salva as alterações.
9. O sistema registra a alteração no histórico.

## Fluxos Alternativos

### FA-01 — Usuário sem permissão de edição

O sistema apresenta os dados somente para leitura.

### FA-02 — Alteração de congregação de origem

A alteração da congregação de origem deverá ser tratada como uma operação administrativa específica e devidamente registrada.

## Fluxos de Exceção

### FE-01 — Dados inválidos

O sistema impede o salvamento e informa os dados que precisam ser corrigidos.

## Pós-condições

Os dados permitidos do orador são atualizados.

## Regras de Negócio Relacionadas

- RN-020
- RN-023
- RN-073
- RN-102

## Entidades Envolvidas

- Orador
- Congregação
- Histórico

## APIs Relacionadas

- PUT /oradores/{id}

## Telas Relacionadas

- Orador
- Editar Orador

# UC-ORA-003 — Consultar Orador

## Objetivo

Permitir a consulta dos dados de um orador e das informações necessárias para seleção durante uma programação.

## Atores

- Usuário
- Administrador Global

## Permissões

Conforme as permissões de consulta do usuário.

## Gatilho

O usuário pesquisa ou seleciona um orador.

## Pré-condições

- Usuário autenticado.
- Orador existente.

## Fluxo Principal

1. O usuário acessa a área de oradores.
2. Pesquisa um orador.
3. O sistema apresenta os resultados.
4. O usuário seleciona um orador.
5. O sistema apresenta seus dados permitidos.
6. O sistema apresenta os temas preparados disponíveis.

## Fluxos Alternativos

### FA-01 — Pesquisa por tema

O usuário informa um tema.

O sistema prioriza os oradores que possuem aquele tema preparado.

### FA-02 — Orador de outra congregação

O sistema permite consultar o orador para fins de convite, respeitando as permissões e a visibilidade dos dados.

A consulta não altera a congregação de origem.

## Pós-condições

Nenhuma informação é alterada.

## Regras de Negócio Relacionadas

- RN-020
- RN-021
- RN-022
- RN-023
- RN-024
- RN-082

## Entidades Envolvidas

- Orador
- Congregação
- Tema
- Tema Preparado

## APIs Relacionadas

- GET /oradores
- GET /oradores/{id}

## Telas Relacionadas

- Oradores
- Detalhes do Orador

## Objetivo

Permitir registrar os temas que um orador está preparado para apresentar.

## Atores

- Coordenador
- Editor, conforme permissão
- Orador vinculado, conforme permissões

## Permissões

O usuário deverá possuir permissão para administrar temas preparados.

## Gatilho

O usuário seleciona Adicionar Tema Preparado.

## Pré-condições

- Orador existente.
- Tema existente.
- Usuário possui permissão.

## Fluxo Principal

1. O usuário acessa o cadastro do orador.
2. Seleciona Temas Preparados.
3. Seleciona um tema.
4. O sistema verifica se o vínculo já existe.
5. O usuário confirma.
6. O sistema registra o tema preparado.
7. O sistema registra a alteração no histórico.

## Fluxos Alternativos

### FA-01 — Tema já preparado

O sistema informa que o orador já possui esse tema preparado e não cria duplicidade.

## Pós-condições

O tema passa a fazer parte dos temas preparados do orador.

## Regras de Negócio Relacionadas

# UC-ORA-005 — Atualizar Temas Preparados

## Objetivo

Permitir adicionar, alterar ou remover os temas preparados de um orador conforme as permissões disponíveis.

## Atores

- Coordenador
- Editor, conforme permissão
- Orador vinculado, conforme permissões
- Administrador Global

## Pré-condições

- Orador existente.
- Usuário autenticado.
- Usuário possui permissão compatível.

## Fluxo Principal

1. O usuário acessa os temas preparados do orador.
2. Seleciona um tema.
3. Escolhe a operação desejada.
4. O sistema valida a operação.
5. O sistema salva a alteração.
6. O sistema registra o evento.

## Operações

- adicionar tema;
- atualizar informações do preparo;
- remover tema preparado.

## Fluxos de Exceção

### FE-01 — Tema inexistente

O sistema impede a operação.

### FE-02 — Duplicidade

O sistema impede a criação de um segundo vínculo entre o mesmo orador e o mesmo tema.

## Pós-condições

A relação entre o orador e seus temas preparados permanece atualizada.

## Regras de Negócio Relacionadas

- RN-021
- RN-034
- RN-102

## Entidades Envolvidas

- Orador
- Tema
- Tema Preparado
- Histórico

## APIs Relacionadas

- PUT /oradores/{id}/temas/{temaId}
- DELETE /oradores/{id}/temas/{temaId}

## Telas Relacionadas

- Temas Preparados

# UC-ORA-007 — Vincular Conta ao Orador

## Objetivo

Permitir vincular uma conta de usuário existente ao cadastro de um orador.

## Atores

- Administrador Global
- Coordenador, conforme permissão
- Orador, durante processo de reivindicação

## Permissões

A vinculação deverá exigir autorização adequada.

## Gatilho

O usuário autorizado seleciona Vincular Conta ou o próprio orador inicia o processo de reivindicação.

## Pré-condições

- Orador cadastrado.
- Conta de usuário existente ou processo de criação de conta iniciado.
- Usuário possui autorização para realizar a vinculação.

## Fluxo Principal

1. O sistema identifica o cadastro do orador.
2. O sistema identifica a conta de usuário.
3. O sistema solicita confirmação da vinculação.
4. O sistema valida a autorização.
5. O sistema associa a conta ao orador.
6. O sistema registra a alteração no histórico.
7. O orador passa a possuir uma conta vinculada.

## Fluxos Alternativos

### FA-01 — Orador ainda não possui conta

O sistema orienta o orador a criar uma conta.

Após a autenticação e validação da identidade, o vínculo poderá ser concluído.

### FA-02 — Conta já vinculada

O sistema informa que o orador já possui uma conta vinculada.

### FA-03 — Reivindicação pelo próprio orador

O orador solicita a reivindicação do cadastro.

O sistema realiza as validações necessárias antes de permitir a vinculação.

## Fluxos de Exceção

### FE-01 — Conta já vinculada a outro orador

O sistema bloqueia a operação.

### FE-02 — Falha de validação

O sistema não realiza a vinculação e informa que não foi possível confirmar a identidade ou autorização.

## Pós-condições

O cadastro do orador passa a possuir uma conta de usuário vinculada.

A ausência de vínculo continua sendo válida para oradores que não possuem conta.

## Regras de Negócio Relacionadas

- RN-035
- RN-036
- RN-102

## Entidades Envolvidas

- Orador
- Usuário
- Histórico

## Casos de Uso Relacionados

- UC-ADM-001 — Autenticar Usuário
- UC-ADM-005 — Gerenciar Usuários

## APIs Relacionadas

- POST /oradores/{id}/vincular-conta

## Telas Relacionadas

- Orador
- Vincular Conta
- Reivindicar Perfil

## Observações

A conta de usuário e o cadastro de orador são conceitos distintos.

Um orador pode existir sem possuir conta de acesso.

Quando existir uma conta vinculada, o sistema poderá utilizar essa associação para permitir que o próprio orador interaja diretamente com convites e demais funcionalidades autorizadas.

O vínculo deverá ser único: uma conta não poderá estar vinculada simultaneamente a dois cadastros de orador.

---

# Considerações Finais

Os Casos de Uso deste documento definem as principais operações relacionadas aos oradores na versão 1.0 do SIPD.

O modelo mantém uma separação importante entre:

**Orador** — Cadastro da pessoa apta a proferir discursos.

**Usuário** — Conta autenticada utilizada para acessar o sistema.

Um orador pode possuir uma conta, mas a existência do orador não depende dela.

A congregação de origem também permanece independente dos convites recebidos. Um orador pode ser convidado por qualquer congregação sem que sua congregação de origem seja alterada.
