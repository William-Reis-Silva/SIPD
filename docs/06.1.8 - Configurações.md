# 06.1.8 — Configurações

> Sistema Inteligente de Programação de Discursos (SIPD)

**Versão:** 1.2

---

# Objetivo

Este documento especifica os Casos de Uso relacionados ao módulo de Configurações do SIPD.

O módulo permite que cada usuário consulte e mantenha suas informações pessoais e preferências de utilização do sistema, respeitando as permissões definidas para seu perfil.

As configurações não devem permitir alterações indevidas em dados administrativos ou dados pertencentes à congregação.

---

# Casos de Uso

| Código | Caso de Uso |
|---------|-------------|
| UC-CONF-001 | Consultar Perfil |
| UC-CONF-002 | Editar Perfil |
| UC-CONF-003 | Alterar Preferências |
| UC-CONF-004 | Consultar Configurações da Congregação |

---

# UC-CONF-001 — Consultar Perfil

## Objetivo

Permitir que o usuário visualize suas informações pessoais cadastradas no SIPD.

## Atores

- Usuário

## Permissões

Todos os perfis autenticados.

## Gatilho

O usuário acessa seu perfil.

## Pré-condições

- Usuário autenticado.

## Fluxo Principal

1. O usuário acessa o menu de Perfil.
2. O sistema identifica o usuário autenticado.
3. O sistema consulta seus dados.
4. O sistema apresenta as informações permitidas.

## Fluxos Alternativos

### FA-01 — Dados incompletos

O sistema apresenta os dados disponíveis e informa quais informações ainda precisam ser preenchidas.

## Fluxos de Exceção

### FE-01 — Falha na consulta

O sistema informa que não foi possível carregar os dados do perfil.

## Pós-condições

Nenhuma informação é alterada.

## Regras de Negócio Relacionadas

- RN-001
- RN-004
- RN-005

## Entidades Envolvidas

- Usuário
- Perfil

## Casos de Uso Relacionados

- UC-ADM-003

## APIs Relacionadas

- GET /perfil

## Telas Relacionadas

- Perfil

---

# UC-CONF-002 — Editar Perfil

## Objetivo

Permitir que o usuário altere seus próprios dados pessoais permitidos pelo sistema.

## Atores

- Usuário

## Permissões

Todos os perfis autenticados.

## Gatilho

O usuário seleciona a opção Editar Perfil.

## Pré-condições

- Usuário autenticado.
- Perfil existente.

## Fluxo Principal

1. O usuário acessa seu Perfil.
2. Seleciona Editar.
3. O sistema apresenta os campos permitidos.
4. O usuário altera seus dados.
5. O usuário confirma a alteração.
6. O sistema valida os dados.
7. O sistema salva as alterações.
8. O sistema registra a operação quando aplicável.

## Fluxos Alternativos

### FA-01 — Dados inválidos

O sistema informa quais dados precisam ser corrigidos.

## Fluxos de Exceção

### FE-01 — Falha ao salvar

O sistema informa que não foi possível salvar as alterações.

Os dados anteriores permanecem preservados.

## Pós-condições

Os dados pessoais permitidos do usuário são atualizados.

## Regras de Negócio Relacionadas

- RN-004
- RN-005
- RN-102

## Entidades Envolvidas

- Usuário

## Casos de Uso Relacionados

- UC-CONF-001
- UC-ADM-003

## APIs Relacionadas

- PUT /perfil

## Telas Relacionadas

- Perfil
- Editar Perfil

# UC-CONF-003 — Alterar Preferências

## Objetivo

Permitir que o usuário configure preferências pessoais de utilização do SIPD.

## Atores

- Usuário

## Permissões

Todos os perfis autenticados.

## Gatilho

O usuário acessa a seção Preferências.

## Pré-condições

- Usuário autenticado.

## Fluxo Principal

1. O usuário acessa Preferências.
2. O sistema apresenta as opções disponíveis.
3. O usuário altera uma ou mais preferências.
4. O usuário salva as alterações.
5. O sistema valida as configurações.
6. O sistema salva as preferências.

## Fluxos Alternativos

### FA-01 — Nenhuma alteração

O usuário abandona a tela sem salvar.

Nenhuma informação é alterada.

## Fluxos de Exceção

### FE-01 — Falha ao salvar

O sistema informa que não foi possível salvar as preferências.

## Pós-condições

As novas preferências passam a ser utilizadas pelo sistema.

## Regras de Negócio Relacionadas

- RN-004
- RN-005

## Entidades Envolvidas

- Usuário

## APIs Relacionadas

- GET /perfil/preferencias
- PUT /perfil/preferencias

## Telas Relacionadas

- Preferências

## Observações

As preferências disponíveis na versão 1.0 deverão ser definidas antes da implementação da interface.

Novas preferências poderão ser adicionadas em versões futuras sem alterar as regras fundamentais do domínio.

# UC-CONF-004 — Consultar Configurações da Congregação

## Objetivo

Permitir que usuários autorizados consultem as configurações operacionais da congregação.

## Atores

- Coordenador
- Editor
- Leitor

## Permissões

- Coordenador: consultar e administrar as configurações permitidas.
- Editor: consultar as configurações necessárias à operação.
- Leitor: apenas visualizar as configurações disponibilizadas.

## Gatilho

O usuário acessa as configurações da congregação.

## Pré-condições

- Usuário autenticado.
- Usuário vinculado à congregação.

## Fluxo Principal

1. O usuário acessa as configurações da congregação.
2. O sistema identifica a congregação do usuário.
3. O sistema verifica suas permissões.
4. O sistema apresenta as configurações permitidas.
5. O usuário consulta as informações.

## Fluxos Alternativos

### FA-01 — Usuário sem permissão de alteração

O sistema apresenta as configurações somente para visualização.

## Fluxos de Exceção

### FE-01 — Acesso não autorizado

O sistema bloqueia o acesso às configurações protegidas.

## Pós-condições

Nenhuma configuração é alterada durante a consulta.

## Regras de Negócio Relacionadas

- RN-002
- RN-003
- RN-005
- RN-090
- RN-091

## Entidades Envolvidas

- Congregação
- Usuário
- Perfil

## APIs Relacionadas

- GET /congregacao/configuracoes

## Telas Relacionadas

- Configurações da Congregação

---

# Considerações Finais

O módulo de Configurações deverá separar claramente:

- configurações pessoais do usuário;
- preferências de utilização;
- configurações operacionais da congregação.

O usuário somente poderá alterar informações para as quais possua permissão.

O perfil Leitor terá acesso somente às informações disponibilizadas para visualização.

As configurações da congregação deverão respeitar o isolamento entre congregações.

Alterações relevantes deverão ser registradas no Histórico quando aplicável.
