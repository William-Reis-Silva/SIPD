# 06.1.5 — Programações

> Sistema Inteligente de Programação de Discursos (SIPD)

**Versão:** 1.2

---

# Objetivo

Este documento especifica os Casos de Uso relacionados ao módulo de Programações do SIPD.

O módulo é responsável pelo planejamento, criação, alteração, acompanhamento e encerramento das programações de discursos das congregações.

A Programação é uma das entidades centrais do sistema e estabelece a relação entre:

- Congregação;
- Data;
- Tema;
- Orador;
- Convites;
- Confirmações;
- Histórico.

# UC-PRO-001 — Criar Programação

## Objetivo

Permitir que um usuário autorizado crie uma nova programação de discurso para sua congregação.

## Atores

- Editor
- Coordenador

## Permissões

- Editor: criar e administrar programações.
- Coordenador: criar e administrar programações.
- Leitor: somente consulta.

## Gatilho

O usuário seleciona a opção Nova Programação.

## Pré-condições

- Usuário autenticado.
- Usuário pertence à congregação.
- Usuário possui permissão para criar programações.
- Não existe outra programação para a mesma congregação na mesma data.

## Fluxo Principal

1. O usuário acessa Nova Programação.
2. Informa a data do discurso.
3. Seleciona o tema.
4. O sistema apresenta informações relacionadas ao tema.
5. O sistema apresenta prioritariamente os oradores preparados para o tema.
6. O usuário seleciona o orador.
7. O sistema executa as validações de negócio.
8. O sistema apresenta eventuais alertas.
9. O usuário confirma a criação.
10. O sistema cria a Programação.
11. O sistema registra o evento no Histórico.
12. A Programação é apresentada na Agenda.

## Fluxos Alternativos

### FA-01 — Orador preparado encontrado

O sistema apresenta primeiro os oradores que possuem o tema selecionado como Tema Preparado.

### FA-02 — Orador não possui o tema preparado

O sistema poderá apresentar outros oradores disponíveis, identificando que eles não possuem o tema como preparado.

### FA-03 — Existem alertas

O sistema apresenta os alertas encontrados antes da gravação.

O usuário poderá corrigir os dados ou prosseguir quando a regra permitir.

### FA-04 — Programação criada sem convite imediato

A Programação poderá ser criada sem que o convite seja enviado imediatamente.

## Fluxos de Exceção

### FE-01 — Data já possui programação

O sistema impede a criação e informa que já existe uma programação para a congregação na data selecionada.

### FE-02 — Dados obrigatórios ausentes

O sistema impede a gravação e informa os campos que precisam ser preenchidos.

### FE-03 — Conflito de programação

O sistema identifica um conflito e informa sua natureza.

Quando o conflito representar um bloqueio, a gravação será impedida.

## Pós-condições

- Uma nova Programação é criada.
- A Programação possui Congregação, Data, Tema, Orador e Status.
- A criação é registrada no Histórico.

## Regras de Negócio Relacionadas

- RN-043
- RN-082
- RN-083

- UC-CONV-001

## APIs Relacionadas

# UC-PRO-002 — Editar Programação

## Objetivo

Permitir que um usuário autorizado altere uma programação existente.

## Atores

- Editor
- Coordenador

## Permissões

- Editor: editar programações da congregação.
- Coordenador: editar programações da congregação.
- Leitor: somente consulta.

## Gatilho

O usuário seleciona uma programação existente e solicita sua edição.

## Pré-condições

- Usuário autenticado.
- Programação existente.
- Usuário possui permissão para editar.
- Programação ainda permite alterações conforme seu estado.

## Fluxo Principal

1. O usuário seleciona a Programação.
2. O sistema apresenta seus dados atuais.
3. O usuário altera os dados necessários.
4. O sistema executa as validações.
5. O sistema apresenta alertas, quando existentes.
6. O usuário confirma as alterações.
7. O sistema salva a Programação.
8. O sistema registra a alteração no Histórico.

## Fluxos Alternativos

### FA-01 — Alteração do orador

Ao alterar o orador, o sistema deverá avaliar os convites e confirmações existentes relacionados à programação.

### FA-02 — Alteração do tema

Ao alterar o tema, o sistema deverá executar novamente as validações relacionadas ao tema e ao orador.

### FA-03 — Alteração da data

O sistema deverá verificar se a nova data está disponível para a congregação.

## Fluxos de Exceção

### FE-01 — Nova data já possui programação

A alteração é impedida.

### FE-02 — Programação não permite alteração

O sistema informa que a programação não pode mais ser alterada devido ao seu estado atual.

## Pós-condições

- A Programação é atualizada.
- As alterações são registradas no Histórico.

## Regras de Negócio Relacionadas

- RN-040
- RN-041
- RN-044
- RN-083
- RN-102

## Entidades Envolvidas

- Programação
- Congregação
- Tema
- Orador
- Histórico

## Casos de Uso Relacionados

- UC-PRO-001
- UC-CONV-001
- UC-CONV-004

## APIs Relacionadas

- PUT /programacoes/{id}

## Telas Relacionadas

- Editar Programação
- Agenda
- Calendário

# UC-PRO-003 — Cancelar Programação

## Objetivo

Permitir que um usuário autorizado cancele uma programação existente.

## Atores

- Editor
- Coordenador

## Permissões

- Editor
- Coordenador

## Gatilho

O usuário seleciona uma programação e solicita seu cancelamento.

## Pré-condições

- Programação existente.
- Usuário autenticado.
- Usuário possui permissão para cancelar.

## Fluxo Principal

1. O usuário seleciona a Programação.
2. Solicita o cancelamento.
3. O sistema apresenta uma confirmação.
4. O usuário confirma.
5. O sistema altera o status da Programação para Cancelada.
6. O sistema registra o cancelamento no Histórico.
7. O sistema processa os Convites relacionados à Programação conforme as regras aplicáveis.

## Fluxos Alternativos

### FA-01 — Cancelamento não confirmado

O usuário cancela a operação.

Nenhuma alteração é realizada.

## Fluxos de Exceção

### FE-01 — Programação já realizada

O sistema impede o cancelamento quando a programação já estiver registrada como realizada.

## Pós-condições

- A Programação fica com status Cancelada.
- O cancelamento permanece registrado no Histórico.

## Regras de Negócio Relacionadas

- RN-044
- RN-055
- RN-054
- RN-102

## Entidades Envolvidas

- Programação
- Convite
- Histórico

## APIs Relacionadas

- POST /programacoes/{id}/cancelar

## Telas Relacionadas

- Detalhes da Programação
- Agenda
- Calendário

## Gatilho

O usuário acessa a Agenda.

## Pré-condições

- Usuário autenticado.
- Usuário possui acesso à congregação.

## Fluxo Principal

2. O sistema apresenta as programações.
3. O usuário poderá consultar uma programação.

5. O usuário poderá utilizar filtros disponíveis.

### FA-01 — Nenhuma programação encontrada

## Fluxos de Exceção

# UC-PRO-006 — Confirmar Realização

## Objetivo

Permitir registrar que uma programação de discurso foi efetivamente realizada.

## Atores

- Editor
- Coordenador

## Permissões

- Editor
- Coordenador

## Gatilho

Após a realização do discurso, o usuário registra a realização da Programação.

## Pré-condições

- Programação existente.
- Data da programação atingida ou ultrapassada.
- Usuário possui permissão para registrar a realização.

## Fluxo Principal

1. O usuário acessa a Programação.
2. Seleciona a opção Confirmar Realização.
3. O sistema apresenta os dados da programação.
4. O usuário confirma que o discurso foi realizado.
5. O sistema altera o status para Realizada.
6. O sistema registra o evento no Histórico.
7. A Programação passa a integrar o histórico de apresentações.

## Fluxos Alternativos

### FA-01 — Programação não realizada

Caso o discurso não tenha ocorrido, o usuário não confirma a realização.

A Programação permanece no estado correspondente até que uma ação válida seja registrada.

## Fluxos de Exceção

### FE-01 — Programação já registrada como realizada

O sistema informa que a realização já foi registrada.

## Pós-condições

- A Programação passa para Realizada.
- O evento é registrado no Histórico.
- Os dados passam a integrar o histórico de apresentações do Orador.

## Regras de Negócio Relacionadas

- RN-055
- RN-070
- RN-071
- RN-073

## Entidades Envolvidas

- Programação
- Orador
- Histórico

## APIs Relacionadas

- POST /programacoes/{id}/realizar

## Telas Relacionadas

- Detalhes da Programação
- Agenda
- Histórico

# Considerações Finais

O módulo de Programações representa o núcleo operacional do SIPD.

A criação e manutenção das programações deverá respeitar as regras de negócio, os estados da programação e as validações executadas pelo Motor de Regras.

Usuários com perfil de Leitor possuem acesso somente para consulta e não podem criar, editar ou cancelar programações.

As operações realizadas sobre uma Programação deverão manter rastreabilidade por meio do Histórico.
