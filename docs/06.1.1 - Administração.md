# 06.1.1 - Administração

> Sistema Inteligente de Programação de Discursos (SIPD)

**Versão:** 1.2

---

# Objetivo

Este documento especifica os Casos de Uso relacionados ao módulo de Administração do SIPD.

O módulo é responsável por:

- autenticação dos Usuários;
- gerenciamento de contas;
- gerenciamento de Perfis;
- controle de permissões;
- controle de acesso ao sistema.

# UC-ADM-001 — Autenticar Usuário

## Objetivo

Permitir que um Usuário acesse o SIPD utilizando suas credenciais de autenticação.

## Atores

- Usuário

## Permissões

Não se aplica.

A autenticação ocorre antes da autorização das funcionalidades.

## Gatilho

O Usuário acessa a tela de Login.

## Pré-condições

- Usuário possui uma conta cadastrada;
- conta está ativa.

## Fluxo Principal

1. O Usuário acessa a tela de Login.
2. Informa o e-mail.
3. Informa a senha.
4. Solicita autenticação.
5. O sistema valida as credenciais.
6. O sistema valida a situação da conta.
7. O sistema estabelece a sessão autenticada.
8. O sistema identifica o Perfil do Usuário.
9. O sistema apresenta a área inicial do sistema.

## Fluxos Alternativos

### FA-01 — Credenciais inválidas

As credenciais informadas não são válidas.

**Resultado:**

O sistema informa que não foi possível autenticar o Usuário.

---

### FA-02 — Conta desativada

A conta existe, porém está desativada.

**Resultado:**

O sistema impede o acesso.

---

## Fluxos de Exceção

### FE-01 — Falha de comunicação

O sistema não consegue concluir a autenticação devido a uma falha de comunicação.

**Resultado:**

O sistema informa que não foi possível realizar a autenticação naquele momento.

## Pós-condições

- Usuário autenticado;
- sessão estabelecida;
- Perfil identificado;
- permissões disponíveis para autorização das funcionalidades.

## Regras de Negócio Relacionadas

- RN-001
- RN-005

## Entidades Envolvidas

- Usuário
- Perfil

## Casos de Uso Relacionados

- UC-ADM-002
- UC-ADM-003
- UC-ADM-004

## APIs Relacionadas

- A definir

## Telas Relacionadas

- Login
- Área inicial

## Observações

A implementação da autenticação poderá utilizar o serviço de autenticação definido na arquitetura do sistema.

A tecnologia utilizada para autenticação não altera as regras de negócio deste Caso de Uso.

# UC-ADM-002 — Recuperar Senha

## Objetivo

Permitir que um Usuário solicite a recuperação de acesso à sua conta.

## Atores

- Usuário

## Permissões

Não se aplica.

A recuperação poderá ser iniciada sem uma sessão autenticada.

## Gatilho

O Usuário seleciona a opção **Esqueci minha senha**.

## Pré-condições

- O Usuário deve possuir um endereço de e-mail informado no processo de recuperação.

## Fluxo Principal

1. O Usuário acessa a opção de recuperação de senha.
2. Informa seu e-mail.
3. Solicita a recuperação.
4. O sistema processa a solicitação.
5. O sistema envia instruções para redefinição da senha quando aplicável.
6. O Usuário acessa as instruções recebidas.
7. Define uma nova senha.
8. O sistema confirma a redefinição.

## Fluxos Alternativos

### FA-01 — Conta não encontrada

O e-mail informado não está associado a uma conta.

**Resultado:**

O sistema não deverá revelar se o endereço possui ou não uma conta cadastrada.

A resposta deverá ser apresentada de forma genérica por segurança.

---

## Fluxos de Exceção

### FE-01 — Falha no envio

O sistema não consegue concluir o envio das instruções.

**Resultado:**

O sistema informa que não foi possível concluir a solicitação.

## Pós-condições

A senha poderá ser redefinida pelo Usuário mediante o processo de recuperação.

## Regras de Negócio Relacionadas

- RN-001
- RN-005

## Entidades Envolvidas

- Usuário

## Casos de Uso Relacionados

- UC-ADM-001
- UC-ADM-003

## APIs Relacionadas

- A definir

## Telas Relacionadas

- Login
- Recuperação de Senha
- Redefinição de Senha

# UC-ADM-003 — Alterar Senha

## Objetivo

Permitir que um Usuário autenticado altere sua senha.

## Atores

- Usuário

## Permissões

Todos os Perfis.

## Gatilho

O Usuário acessa a funcionalidade de alteração de senha.

## Pré-condições

- Usuário autenticado;
- sessão válida.

## Fluxo Principal

1. O Usuário acessa a área de Perfil ou Segurança.
2. Informa a senha atual, quando exigida.
3. Informa a nova senha.
4. Confirma a nova senha.
5. Solicita a alteração.
6. O sistema valida os dados.
7. O sistema altera a senha.
8. O sistema informa o resultado da operação.

## Fluxos Alternativos

### FA-01 — Nova senha inválida

A nova senha não atende aos requisitos definidos pelo sistema.

**Resultado:**

O sistema solicita uma nova senha válida.

---

### FA-02 — Confirmação diferente

A confirmação da nova senha não corresponde à nova senha.

**Resultado:**

O sistema solicita a confirmação novamente.

## Fluxos de Exceção

### FE-01 — Falha na alteração

O sistema não consegue concluir a alteração.

**Resultado:**

A senha anterior permanece válida e o sistema informa a falha.

## Pós-condições

A nova senha passa a ser utilizada para autenticação da conta.

## Regras de Negócio Relacionadas

- RN-001
- RN-005

## Entidades Envolvidas

- Usuário

## Casos de Uso Relacionados

- UC-ADM-001
- UC-ADM-002

## APIs Relacionadas

- A definir

## Telas Relacionadas

- Perfil
- Segurança

# UC-ADM-004 — Encerrar Sessão

## Objetivo

Permitir que o Usuário encerre sua sessão de forma segura.

## Atores

- Usuário

## Permissões

Todos os Perfis.

## Gatilho

O Usuário seleciona a opção **Sair**.

## Pré-condições

- Usuário autenticado;
- sessão válida.

## Fluxo Principal

1. O Usuário seleciona a opção **Sair**.
2. O sistema encerra a sessão.
3. O sistema remove os dados locais relacionados à sessão.
4. O sistema redireciona o Usuário para a tela de Login.

## Fluxos Alternativos

Não se aplica.

## Fluxos de Exceção

### FE-01 — Falha ao encerrar sessão

O sistema encontra uma falha durante o processo de encerramento.

**Resultado:**

O sistema deverá impedir a permanência em áreas protegidas sempre que possível e solicitar nova autenticação quando necessário.

## Pós-condições

- A sessão do Usuário foi encerrada;
- o acesso às áreas protegidas exige nova autenticação.

## Regras de Negócio Relacionadas

- RN-005

## Entidades Envolvidas

- Usuário

## Casos de Uso Relacionados

- UC-ADM-001

## APIs Relacionadas

- A definir

# UC-ADM-005 — Gerenciar Usuários

## Objetivo

Permitir o gerenciamento dos Usuários dentro do escopo de Congregação permitido pelo Perfil do Usuário autenticado.

## Atores

- Usuário

## Permissões

Definidas conforme o Perfil:

- Administrador Global;
- Coordenador;
- Editor, quando possuir a permissão correspondente.

O Leitor possui somente acesso de consulta quando autorizado.

## Gatilho

O Usuário acessa a área de gerenciamento de Usuários.

## Pré-condições

- Usuário autenticado;
- possuir permissão para consultar ou administrar Usuários.

## Funcionalidades

O Caso de Uso poderá contemplar:

- consultar Usuários;
- visualizar dados permitidos;
- cadastrar ou convidar Usuário;
- editar dados permitidos;
- ativar Usuário;
- desativar Usuário;
- consultar situação da conta.

## Fluxo Principal

1. O Usuário acessa o gerenciamento de Usuários.
2. O sistema verifica suas permissões.
3. O sistema apresenta os Usuários dentro do escopo permitido.
4. O Usuário seleciona uma operação.
5. O sistema valida a permissão para a operação.
6. O sistema executa a operação.
7. O sistema registra a alteração quando aplicável.

## Fluxos Alternativos

### FA-01 — Usuário somente consulta

O Perfil possui apenas permissão de leitura.

**Resultado:**

O sistema permite a consulta, mas não apresenta operações de alteração.

---

### FA-02 — Usuário fora do escopo

O Usuário selecionado pertence a uma Congregação fora do escopo permitido.

**Resultado:**

A operação é negada.

## Fluxos de Exceção

### FE-01 — Operação não autorizada

O Usuário não possui a permissão necessária.

**Resultado:**

O sistema impede a operação.

## Pós-condições

Quando houver alteração:

- os dados do Usuário são atualizados;
- a operação é registrada conforme as regras de auditoria.

## Regras de Negócio Relacionadas

- RN-003
- RN-005
- RN-102

## Entidades Envolvidas

- Usuário
- Perfil
- Congregação

## Casos de Uso Relacionados

- UC-ADM-006
- UC-ADM-007

## APIs Relacionadas

## Telas Relacionadas

- Cadastro de Usuário

# UC-ADM-006 — Gerenciar Perfis

## Objetivo

Permitir o gerenciamento do Perfil atribuído a um Usuário, respeitando as permissões administrativas do sistema.

## Atores

- Administrador Global
- Usuário autorizado

## Permissões

A operação depende das permissões administrativas atribuídas ao Perfil.

## Gatilho

O Usuário autorizado acessa o gerenciamento de Perfis.

## Pré-condições

- Usuário autenticado;
- possuir permissão para gerenciar Perfis.

## Fluxo Principal

1. O Usuário acessa o gerenciamento de Perfis.
2. O sistema verifica sua autorização.
3. O sistema apresenta os Perfis disponíveis.
4. O Usuário seleciona o Perfil que deseja atribuir ou alterar.
5. O sistema valida a operação.
6. O sistema registra a alteração.

## Fluxos Alternativos

### FA-01 — Perfil não permitido

O Perfil selecionado não pode ser atribuído pelo Usuário atual.

**Resultado:**

O sistema impede a operação.

---

### FA-02 — Administrador Global

O Administrador Global executa uma operação administrativa permitida.

**Resultado:**

O sistema aplica a alteração conforme as regras de segurança.

## Fluxos de Exceção

### FE-01 — Operação não autorizada

O Usuário não possui permissão suficiente.

**Resultado:**

A alteração é negada.

## Pós-condições

O Usuário selecionado passa a possuir o Perfil autorizado.

## Regras de Negócio Relacionadas

- RN-003
- RN-005
- RN-102

## Entidades Envolvidas

- Usuário
- Perfil
- Congregação

## Casos de Uso Relacionados

- UC-ADM-005
- UC-ADM-007

## APIs Relacionadas

- A definir

## Telas Relacionadas

- Usuários
- Perfis

## Observações

Os Perfis da versão 1.0 são:

- Administrador Global;
- Coordenador;
- Editor;
- Leitor.

A atribuição do Perfil **Administrador Global** deverá possuir controle específico de segurança.

# UC-ADM-007 — Gerenciar Permissões

## Objetivo

Controlar as permissões disponíveis no sistema e sua associação aos Perfis.

## Atores

- Administrador Global

## Permissões

- Permissão administrativa global para gerenciamento de permissões.

## Gatilho

O Administrador Global acessa a área de Permissões.

## Pré-condições

- Usuário autenticado;
- Usuário possui Perfil Administrador Global;
- operação autorizada.

## Fluxo Principal

1. O Administrador Global acessa a área de Permissões.
2. O sistema apresenta os Perfis e suas permissões configuradas.
3. O Administrador Global consulta as permissões.
4. Quando permitido pela versão do sistema, realiza uma alteração.
5. O sistema valida a operação.
6. O sistema salva a configuração.
7. O sistema registra a alteração para fins de auditoria.

## Fluxos Alternativos

### FA-01 — Permissões fixas

Na versão 1.0, as permissões são definidas pelo sistema de acordo com cada Perfil.

**Resultado:**

O Administrador Global poderá consultar a configuração, mas alterações personalizadas poderão não estar disponíveis.

## Fluxos de Exceção

### FE-01 — Operação não autorizada

Um Usuário sem permissão tenta acessar a funcionalidade.

**Resultado:**

O acesso é negado.

## Pós-condições

Quando uma alteração for permitida:

- a configuração de permissões é atualizada;
- a alteração é registrada para auditoria.

## Regras de Negócio Relacionadas

- RN-005
- RN-091
- RN-102

## Entidades Envolvidas

- Perfil
- Usuário

## Casos de Uso Relacionados

- UC-ADM-005
- UC-ADM-006

## APIs Relacionadas

- A definir

## Telas Relacionadas

- Permissões
- Perfis

## Observações

Na versão 1.0, o modelo de autorização será baseado nos Perfis definidos pelo sistema.

Permissões personalizadas por Usuário ou por Congregação poderão ser avaliadas em versões futuras.

# Considerações Finais

Os Casos de Uso descritos neste documento representam as funcionalidades administrativas previstas para a versão 1.0 do SIPD.

O módulo de Administração fornece a base para:

- autenticação;
- autorização;
- gerenciamento de Usuários;
- gerenciamento de Perfis;
- controle de permissões;
- segurança de acesso.

Os demais módulos utilizarão essas funcionalidades para determinar quem poderá consultar, criar, alterar ou executar cada operação.
