# 06.1.6 — Convites

> Sistema Inteligente de Programação de Discursos (SIPD)

**Versão:** 1.1

---

# Objetivo

Este documento especifica os Casos de Uso relacionados ao módulo de Convites do SIPD.

O módulo é responsável pelo processo de convite de oradores para apresentações, desde a criação e envio até a resposta do orador e o registro da confirmação.

O módulo também mantém a rastreabilidade das respostas e dos acontecimentos relacionados aos convites.

# UC-CONV-001 — Criar Convite

## Objetivo

Permitir que um usuário autorizado crie um convite para um orador relacionado a uma Programação.

## Atores

- Editor
- Coordenador

## Permissões

- Editor
- Coordenador

Usuários com perfil Leitor não podem criar convites.

## Gatilho

O usuário seleciona uma Programação e solicita a criação de um convite.

## Pré-condições

- Usuário autenticado.
- Usuário possui permissão para administrar a Programação.
- Programação existente.
- Orador cadastrado.
- A Programação ainda permite o envio de convite.

## Fluxo Principal

1. O usuário acessa a Programação.
2. Seleciona a opção Criar Convite.
3. Seleciona ou confirma o Orador.
4. O sistema apresenta os dados da Programação.
5. O usuário confirma a criação.
6. O sistema cria o Convite com status Criado.
7. O sistema registra o evento no Histórico.

## Fluxos Alternativos

### FA-01 — Orador diferente

O usuário seleciona outro Orador disponível para a Programação.

### FA-02 — Convite já existente

O sistema informa que já existe um Convite relacionado à Programação e ao Orador selecionado.

## Fluxos de Exceção

### FE-01 — Programação não permite convite

O sistema impede a criação do Convite.

## Pós-condições

- Convite criado.
- Convite vinculado à Programação.
- Convite vinculado ao Orador.
- Evento registrado no Histórico.

## Regras de Negócio Relacionadas

- RN-050
- RN-051
- RN-054
- RN-070
- RN-071

## Entidades Envolvidas

- Convite
- Programação
- Orador
- Histórico

## Casos de Uso Relacionados

- UC-PRO-001
- UC-CONV-002

## APIs Relacionadas

- POST /convites

## Telas Relacionadas

- Detalhes da Programação
- Novo Convite

# UC-CONV-002 — Enviar Convite

## Objetivo

Permitir o envio de um Convite criado para o Orador.

## Atores

- Editor
- Coordenador
- Sistema

## Permissões

- Editor
- Coordenador

## Gatilho

O usuário seleciona Enviar Convite.

## Pré-condições

- Convite existente.
- Convite no estado Criado.
- Orador definido.
- Programação válida.

## Fluxo Principal

1. O usuário seleciona o Convite.
2. Solicita o envio.
3. O sistema valida o Convite.
4. O sistema envia a notificação ao Orador.
5. O sistema altera o status para Enviado.
6. O sistema registra o envio no Histórico.

## Fluxos Alternativos

### FA-01 — Orador possui conta

O Convite é disponibilizado diretamente para o Orador por meio do sistema.

### FA-02 — Orador não possui conta

O sistema utiliza o meio de contato disponível para o Orador, conforme os mecanismos definidos para a versão 1.0.

## Fluxos de Exceção

### FE-01 — Falha no envio

O sistema informa que não foi possível enviar o Convite.

O Convite permanece disponível para uma nova tentativa.

## Pós-condições

- Convite enviado ou tentativa registrada.
- Status alterado para Enviado quando o envio for concluído.
- Histórico atualizado.

## Regras de Negócio Relacionadas

- RN-050
- RN-051
- RN-053
- RN-070
- RN-071

## Entidades Envolvidas

- Convite
- Orador
- Programação
- Histórico

## APIs Relacionadas

- POST /convites/{id}/enviar

## Telas Relacionadas

- Detalhes do Convite

# UC-CONV-005 — Aceitar Convite

## Objetivo

Permitir que o Orador aceite um Convite recebido.

## Atores

- Orador

## Permissões

Orador destinatário do Convite.

## Gatilho

O Orador seleciona Aceitar Convite.

## Pré-condições

- Convite existente.
- Convite no estado Enviado.
- Orador é o destinatário do Convite.
- Convite não está cancelado ou expirado.

## Fluxo Principal

1. O Orador acessa o Convite.
2. Consulta os dados da Programação.
3. Seleciona Aceitar.
4. O sistema valida o Convite.
5. O sistema altera o status para Aceito.
6. O sistema registra a resposta no Histórico.
7. O sistema disponibiliza o formulário de confirmação.

## Fluxos Alternativos

### FA-01 — Orador possui conta

A resposta é registrada diretamente pelo sistema.

### FA-02 — Orador não possui conta

A resposta poderá ser registrada por meio do mecanismo disponibilizado para o convite.

## Fluxos de Exceção

### FE-01 — Convite expirado

O sistema impede o aceite.

### FE-02 — Convite cancelado

O sistema impede o aceite.

## Pós-condições

- Convite passa para Aceito.
- Sistema disponibiliza a confirmação.
- Histórico atualizado.

# UC-CONV-007 — Confirmar Convite

## Objetivo

Permitir que o Orador envie os dados complementares necessários após aceitar um Convite.

## Atores

- Orador

## Permissões

Orador destinatário do Convite.

## Gatilho

O Orador acessa o formulário de confirmação após aceitar o Convite.

## Pré-condições

- Convite aceito.
- Confirmação ainda não enviada.
- Orador é o destinatário do Convite.

## Fluxo Principal

1. O Orador acessa o formulário de confirmação.
2. O sistema apresenta os dados da Programação.
3. O Orador informa os dados solicitados.
4. Informa o cântico inicial, quando aplicável.
5. Informa a utilização de imagens, quando aplicável.
6. Anexa arquivos, quando necessário.
7. Informa observações, quando necessário.
8. Confirma sua permanência até o final da reunião.
9. Envia a confirmação.
10. O sistema valida os dados.
11. O sistema registra a Confirmação.
12. O sistema altera a Programação para Confirmada.
13. O sistema registra o evento no Histórico.

## Fluxos Alternativos

### FA-01 — Sem anexos

O Orador envia a confirmação sem anexar arquivos.

### FA-02 — Sem observações

O Orador envia a confirmação sem observações adicionais.

## Fluxos de Exceção

### FE-01 — Dados obrigatórios ausentes

O sistema impede o envio e informa os dados necessários.

### FE-02 — Arquivo inválido

O sistema rejeita o arquivo e informa o motivo.

## Pós-condições

- Confirmação registrada.
- Programação passa para Confirmada.
- Histórico atualizado.

# Considerações Finais

O módulo de Convites controla a comunicação entre a Congregação e o Orador durante o processo de programação de discursos.

O Convite deverá permanecer vinculado à Programação e ao Orador durante todo o seu ciclo de vida.

As alterações de estado deverão ser registradas no Histórico, garantindo rastreabilidade das respostas e ações realizadas.

A existência ou não de uma conta de usuário para o Orador não altera sua condição de Orador. Quando possuir uma conta vinculada, o Orador poderá interagir diretamente com os Convites por meio do sistema.

Usuários com perfil Leitor possuem acesso somente para consulta e não podem criar, enviar, cancelar ou administrar Convites.
