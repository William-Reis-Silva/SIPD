# 06.1.2 - Congregações

> Sistema Inteligente de Programação de Discursos (SIPD)

**Versão:** 1.2

---

# Objetivo

Este documento especifica os Casos de Uso relacionados ao módulo de Congregações do SIPD.

O módulo é responsável pelo cadastro e gerenciamento das congregações, seus dados administrativos e o relacionamento dos usuários com cada congregação.

O módulo também define o nível de acesso dos usuários às informações da congregação, respeitando suas permissões.

| UC-CGR-003 | Gerenciar Usuários da Congregação |

# UC-CGR-001 — Consultar Congregação

## Objetivo

Permitir que o usuário consulte os dados da congregação à qual está vinculado.

## Atores

- Usuário

## Permissões

- Coordenador
- Editor
- Leitor
- Administrador Global

## Gatilho

O usuário acessa a área de informações da congregação.

## Pré-condições

- Usuário autenticado.
- Usuário vinculado a uma congregação.

## Fluxo Principal

1. O usuário acessa a área Congregação.
2. O sistema identifica a congregação vinculada ao usuário.
3. O sistema verifica as permissões do usuário.
4. O sistema apresenta os dados da congregação.
5. O usuário consulta as informações disponíveis.

## Fluxos Alternativos

### FA-01 — Administrador Global

O Administrador Global poderá consultar congregações da plataforma conforme suas permissões administrativas.

### FA-02 — Usuário somente leitura

O usuário com permissão de leitura poderá visualizar os dados, mas não poderá alterá-los.

## Fluxos de Exceção

### FE-01 — Congregação não encontrada

O sistema informa que a congregação não foi localizada ou não está disponível para o usuário.

## Pós-condições

Nenhum dado é alterado.

## Regras de Negócio Relacionadas

- RN-010
- RN-011
- RN-003
- RN-090
- RN-091

## Entidades Envolvidas

- Congregação
- Usuário
- Perfil

## Casos de Uso Relacionados

- UC-CGR-002
- UC-CGR-003

## APIs Relacionadas

- GET /congregacoes/{id}

## Telas Relacionadas

- Congregação
- Dados da Congregação

## Observações

A consulta deverá respeitar as permissões do usuário.

Usuários sem permissão de edição terão acesso somente à visualização dos dados.

# UC-CGR-002 — Atualizar Dados da Congregação

## Objetivo

Permitir que usuários autorizados atualizem os dados administrativos da congregação.

## Atores

- Coordenador
- Administrador Global

## Permissões

- Coordenador — editar dados da própria congregação.
- Administrador Global — administrar congregações conforme suas permissões.

## Gatilho

O usuário autorizado seleciona a opção de editar os dados da congregação.

## Pré-condições

- Usuário autenticado.
- Usuário possui permissão de edição.
- Congregação existente.

## Fluxo Principal

1. O usuário acessa os dados da congregação.
2. Seleciona a opção Editar.
3. O sistema verifica a permissão de edição.
4. O sistema apresenta os dados editáveis.
5. O usuário altera os dados necessários.
6. O usuário confirma a alteração.
7. O sistema valida os dados.
8. O sistema salva as alterações.
9. O sistema registra a alteração no histórico.

## Fluxos Alternativos

### FA-01 — Usuário sem permissão de edição

O sistema apresenta os dados somente para leitura e não disponibiliza a alteração.

### FA-02 — Nenhuma alteração realizada

O usuário cancela a operação ou não modifica os dados.

**Resultado:**

Nenhuma alteração é registrada.

## Fluxos de Exceção

### FE-01 — Dados inválidos

O sistema informa quais dados precisam ser corrigidos e não salva a alteração.

### FE-02 — Falha ao salvar

O sistema informa que não foi possível salvar as alterações.

Os dados anteriores permanecem preservados.

## Pós-condições

Os dados válidos da congregação são atualizados e a alteração é registrada no histórico.

## Regras de Negócio Relacionadas

- RN-010
- RN-003
- RN-073
- RN-102

## Entidades Envolvidas

- Congregação
- Usuário
- Histórico

## Casos de Uso Relacionados

- UC-CGR-001

## APIs Relacionadas

- PUT /congregacoes/{id}

## Telas Relacionadas

- Congregação
- Editar Congregação

## Observações

O Coordenador poderá editar somente os dados da própria congregação.

O Administrador Global possui acesso administrativo global.

Usuários com permissão somente de leitura não poderão alterar os dados.

# UC-CGR-003 — Gerenciar Usuários da Congregação

## Objetivo

Permitir que usuários autorizados consultem e gerenciem os usuários vinculados à congregação.

## Atores

- Coordenador
- Administrador Global

## Permissões

- Coordenador — gerenciar usuários da própria congregação.
- Administrador Global — administrar usuários conforme suas permissões.
- Usuários com permissão somente de leitura poderão apenas consultar os usuários.

## Gatilho

O usuário acessa a área Usuários da Congregação.

## Pré-condições

- Usuário autenticado.
- Congregação existente.
- Usuário possui permissão compatível com a operação.

## Fluxo Principal

1. O usuário acessa a lista de usuários da congregação.
2. O sistema apresenta os usuários vinculados.
3. O sistema apresenta as ações disponíveis conforme as permissões.
4. O usuário autorizado seleciona uma operação.
5. O sistema valida a permissão.
6. O sistema executa a operação.
7. O sistema registra a alteração quando aplicável.

## Funcionalidades

O gerenciamento poderá incluir:

- consultar usuários;
- convidar usuário;
- editar dados permitidos;
- atribuir perfil conforme permissão;
- ativar usuário;
- desativar usuário;
- remover vínculo com a congregação, quando permitido.

## Fluxos Alternativos

### FA-01 — Consulta

Usuário com permissão somente de leitura acessa a lista.

**Resultado:**

O sistema permite visualizar os usuários, mas não apresenta ações de alteração.

### FA-02 — Convite de novo usuário

1. O usuário autorizado seleciona Convidar Usuário.
2. Informa o perfil a ser atribuído (e, opcionalmente, um rótulo para identificar o convite).
3. O sistema gera um código/link de convite, válido por 7 dias.
4. O usuário autorizado compartilha o código/link manualmente com o convidado (ex.: WhatsApp).
5. O usuário convidado cria ou acessa sua conta e informa o código para vincular-se à congregação.
6. Após a vinculação, o usuário passa a fazer parte da congregação, com o perfil definido no convite.

### FA-03 — Alteração de perfil

O sistema permite alterar o perfil do usuário quando o operador possuir permissão para essa ação.

A atribuição do perfil Administrador Global permanece restrita ao Administrador Global.

### FA-04 — Desativação

1. O usuário autorizado seleciona um usuário.
2. Seleciona Desativar.
3. O sistema solicita confirmação.
4. O sistema desativa o usuário ou seu acesso conforme as regras de segurança.

### FA-05 — Transferência entre congregações

1. Um usuário que já possui cadastro em outra congregação recebe um convite de código/link de uma nova congregação.
2. Ao informar o código do convite, o sistema identifica que o usuário já possui cadastro.
3. O sistema substitui a congregação e o perfil do usuário pelos definidos no convite, e marca o usuário como ativo.

**Restrição:** se o usuário for o único Coordenador ativo da congregação de origem, a transferência é bloqueada até que outro usuário assuma o perfil de Coordenador ali (RN-028).

## Fluxos de Exceção

### FE-01 — Usuário sem permissão

O sistema bloqueia a operação e informa que o usuário não possui permissão suficiente.

### FE-02 — Usuário de outra congregação

O sistema impede que um Coordenador ou outro usuário local administre um usuário pertencente a outra congregação.

### FE-03 — Falha na operação

O sistema informa que não foi possível concluir a operação e preserva os dados anteriores.

## Pós-condições

Quando uma operação de gerenciamento for concluída:

- os dados do usuário são atualizados;
- o vínculo com a congregação é preservado ou alterado conforme a operação;
- alterações relevantes são registradas no histórico.

## Observações

O vínculo entre usuário e congregação deverá respeitar as regras definidas no domínio.

O Coordenador possui capacidade de edição dentro da própria congregação.

O Editor não possui permissão administrativa para editar os dados da congregação ou gerenciar usuários, salvo quando uma permissão específica futura permitir essa operação.

Usuários com acesso somente de leitura poderão consultar as informações, mas não poderão modificá-las.

---

# Considerações Finais

Os Casos de Uso deste documento definem as operações relacionadas às congregações na versão 1.0 do SIPD.

O módulo deverá respeitar a separação entre visualização, edição e administração global, garantindo que cada usuário tenha acesso somente às operações permitidas pelo seu perfil.
