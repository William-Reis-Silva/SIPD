# 06.1.9 — Inteligência

> Sistema Inteligente de Programação de Discursos (SIPD)

**Versão:** 1.2

---

# Objetivo

Este documento especifica os Casos de Uso relacionados ao módulo de Inteligência do SIPD.

O módulo é responsável por analisar os dados disponíveis no sistema e apresentar informações úteis para apoiar a tomada de decisão do usuário.

A Inteligência não substitui a decisão do usuário. Seu objetivo é identificar situações, gerar alertas, apresentar pendências, sugerir opções e facilitar a operação do sistema.

# UC-INT-001 — Sugerir Oradores

## Objetivo

Apresentar oradores que possuam maior compatibilidade com uma programação ou tema selecionado.

## Atores

- Coordenador
- Editor

## Permissões

- Coordenador: acesso às sugestões da congregação.
- Editor: acesso às sugestões necessárias para a programação.
- Leitor: não poderá utilizar a sugestão para criar ou alterar programações.

## Gatilho

O usuário seleciona um tema durante a criação ou edição de uma programação.

## Pré-condições

- Usuário autenticado.
- Tema selecionado.
- Existência de oradores cadastrados.

## Fluxo Principal

1. O usuário seleciona um tema.
2. O sistema identifica os oradores preparados para esse tema.
3. O sistema analisa os dados disponíveis.
4. O sistema identifica os oradores mais adequados.
5. O sistema apresenta as sugestões.
6. O usuário escolhe o orador desejado.

## Critérios considerados

Sempre que houver dados disponíveis, o sistema poderá considerar:

- tema preparado;
- histórico de apresentações;
- utilização recente do tema;
- disponibilidade;
- programações futuras;
- conflitos;
- relação com a congregação.

## Fluxos Alternativos

### FA-01 — Nenhum orador preparado

O sistema informa que não encontrou oradores cadastrados como preparados para o tema.

### FA-02 — Vários oradores compatíveis

O sistema apresenta uma lista ordenada por relevância.

## Fluxos de Exceção

### FE-01 — Falha na análise

O sistema informa que não foi possível gerar as sugestões.

O usuário poderá realizar a seleção manualmente.

## Pós-condições

Nenhum dado é alterado automaticamente.

A escolha final permanece sob responsabilidade do usuário.

## Regras de Negócio Relacionadas

- RN-022
- RN-082
- RN-095

## Entidades Envolvidas

- Tema
- Tema Preparado

## Casos de Uso Relacionados

- UC-PRO-001
- UC-ORA-003

## APIs Relacionadas

- GET /inteligencia/oradores/sugestoes

## Telas Relacionadas

- Nova Programação
- Editar Programação

# UC-INT-002 — Detectar Conflitos

## Objetivo

Identificar conflitos que possam comprometer uma programação antes de sua gravação.

## Atores

- Sistema

## Gatilho

O usuário cria ou altera uma programação.

## Pré-condições

- Dados da programação informados.

## Fluxo Principal

1. O usuário informa os dados da programação.
2. O sistema executa as validações.
3. O sistema verifica possíveis conflitos.
4. O sistema classifica os resultados.
5. O sistema apresenta os conflitos encontrados.

## Possíveis conflitos

- programação duplicada;
- orador já comprometido;
- data incompatível;
- convite ou programação conflitante;
- outras inconsistências previstas pelas regras de negócio.

## Fluxos Alternativos

### FA-01 — Nenhum conflito

O sistema informa que não foram encontrados conflitos.

## Fluxos de Exceção

### FE-01 — Falha na validação

O sistema informa que não foi possível concluir a análise.

## Pós-condições

Os conflitos identificados ficam disponíveis para análise do usuário.

Quando um conflito representar um bloqueio, a gravação deverá ser impedida.

## Regras de Negócio Relacionadas

- RN-041
- RN-083
- RN-091

## Entidades Envolvidas

- Programação
- Orador
- Convite

## Casos de Uso Relacionados

- UC-PRO-001
- UC-PRO-002

## APIs Relacionadas

- POST /inteligencia/conflitos/verificar

## Telas Relacionadas

- Nova Programação
- Editar Programação

# UC-INT-003 — Alertar Repetição de Tema

## Objetivo

Alertar o usuário quando a utilização de um tema puder representar uma repetição recente.

## Atores

- Sistema

## Gatilho

O usuário seleciona um tema para uma programação.

## Pré-condições

- Tema selecionado.
- Existência de histórico ou programação futura para análise.

## Fluxo Principal

1. O sistema identifica o tema selecionado.
2. Consulta as programações relevantes.
3. Verifica a utilização recente do tema.
4. Verifica programações futuras.
5. Gera alerta quando uma condição definida pelas regras for encontrada.
6. Apresenta o alerta ao usuário.

## Fluxos Alternativos

### FA-01 — Nenhuma repetição identificada

Nenhum alerta é apresentado.

## Fluxos de Exceção

### FE-01 — Falha na consulta

O sistema informa que não foi possível verificar a utilização do tema.

## Pós-condições

O usuário recebe a informação necessária para decidir se continuará com a programação.

## Regras de Negócio Relacionadas

- RN-080
- RN-081

## Entidades Envolvidas

- Tema
- Programação
- Histórico da Programação

## APIs Relacionadas

- GET /inteligencia/temas/alertas

## Telas Relacionadas

- Nova Programação
- Editar Programação

# UC-INT-004 — Exibir Pendências

## Objetivo

Apresentar ao usuário situações que exigem atenção ou ação.

## Atores

- Coordenador
- Editor

## Permissões

Conforme as permissões do usuário.

## Gatilho

O usuário acessa o sistema ou o Dashboard.

## Fluxo Principal

1. O sistema identifica o usuário.
2. Consulta as informações relacionadas à sua congregação.
3. Analisa situações pendentes.
4. Classifica as pendências.
5. Apresenta as pendências ao usuário.

## Exemplos

- convites aguardando resposta;
- confirmações pendentes;
- programações próximas sem confirmação;
- conflitos;
- outras situações que necessitem de atenção.

## Fluxos Alternativos

### FA-01 — Nenhuma pendência

O sistema informa que não existem pendências relevantes.

## Regras de Negócio Relacionadas

- RN-097

## Entidades Envolvidas

- Convite

# Considerações Finais

O módulo de Inteligência tem caráter assistivo.

O sistema poderá analisar informações e apresentar sugestões, alertas, indicadores e pendências, mas decisões operacionais que não estejam explicitamente definidas como bloqueios continuarão sob responsabilidade do usuário autorizado.

As sugestões deverão ser baseadas nos dados disponíveis e não deverão alterar automaticamente uma programação sem uma ação autorizada do usuário.

O acesso às informações deverá respeitar o escopo da congregação e as permissões do usuário.
